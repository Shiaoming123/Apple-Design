# 设计交付合同

对涉及多个状态、页面或共享组件的工作，以下字段构成最小可评审交付。快速审查只保留相关字段；不要为了模板编造产品事实。

```text
范围与状态：受影响表面；LOCKED / EXISTING / EXPLORE；本次不做什么。
当前证据：真实截图、代码、调用者、用户反馈或已批准参考；未知项明确标注。
问题与目标：用户任务为何受阻；完成后可观察到什么。
决策：保留什么；改变什么；至少一个被拒绝方案及理由。
状态与可访问性：默认、空/忙碌/错误/恢复；键盘/触摸路径、焦点和文字增长。
实施边界：触及的共享组件、token、平台差异；不改变的业务与数据语义。
验证：已执行命令或操作、环境、结果；未执行检查及原因。
```

## 三种简化方式

| 工作 | 必须保留 | 可省略 |
| --- | --- | --- |
| 快速审查 | 范围与状态、当前证据、问题与目标、最小改动 | 实施文件与完整状态矩阵 |
| 已授权实现 | 全部字段；列出真实改动和验证结果 | 没有发生的平台可省略，但不能声称通过 |
| 新方向探索 | 范围与状态、证据、2–3 个方向、取舍、待批准项 | 代码变更和“已验证”结论 |

## 判定完成

没有“当前证据”时是建议，不是审查；没有“验证”时是方案，不是完成；没有状态标记时，任何“优化”都不能推翻已批准设计。把这些边界写出来比增加颜色、圆角或动效参数更重要。
