# 主要页面设计手册
本手册是原创工程案例，不是 HIG 的逐页翻译，也不是 Apple 官方布局。用于从需求产生可审查的页面方案，而不是只给一张漂亮默认态。
阅读路线：页面合同 → 主工作区 → 搜索 → 编辑 → 日历 → 设置 → 首次使用 → 详情/阅读 → 交付。

## 1. 先写页面合同
每个关键页面明确这六件事，已有产品可直接引用既有合同：

| 字段 | 示例：个人任务的“今天”页 |
| --- | --- |
| 使用者与时刻 | 开始工作前，判断下一项值得做的任务 |
| 一句话目的 | 看清今天承诺的事项，并开始或完成其中一项 |
| 主要对象与动作 | 任务；打开、创建、完成。任务不是统计卡片的附属品 |
| 第一屏的信息顺序 | 当前日期/范围 → 主要动作 → 紧急或计划中的对象 → 次要信息 |
| 成功与恢复 | 保存结果可见，返回列表仍在原位置，误操作可恢复 |
| 不在本页解决 | 账号管理、完整周报、主题配置，不因为有空白就塞进来 |

做图前用一句话解释第一屏。若只能解释“有哪些卡片”，通常还没有确定用户任务。
不要把“一个主要动作”硬解释为全屏只能一个按钮；列表对象可以各自有常用操作，但视觉强调不能全部同级。

## 2. 主工作区：列表—详情
### 为什么这样组织
列表支持比较和选择，详情支持理解单个对象；并列显示适合反复切换对象。小窗口依次进入更易阅读。两种布局应该共享同一个选择状态，而不是维护两套任务副本。

### 参考结构
```text
宽窗口
导航        当前列表 / 搜索 / 新建            当前任务详情
目的地      筛选范围与结果数量               标题 / 状态 / 编辑
分组        任务标题 → 计划时间 → 所属清单    备注 / 操作历史
            完成入口与打开详情分别可操作

窄窗口
列表标题 / 搜索 / 新建
任务列表 → 点开任务 → 详情页
                     返回同一筛选与滚动位置
```

这里是信息关系，不是固定像素稿。分栏是否出现由可读宽度、缩放和任务决定。
不要在宽屏同时出现固定详情、覆盖式详情和编辑弹层三份对象副本。

### 交互过程
1. 从列表打开任务：保存 selectedId 和滚动锚点；详情标题接收合适的朗读上下文。
2. 切换对象：更新详情内容，避免整个工作区淡出；如有未保存草稿，先按产品规则处理。
3. 编辑对象：继续在详情容器编辑，或打开独立短任务表单；不要两者一起出现。
4. 保存成功：列表和详情引用同一已提交事实；显示结果，再结束忙碌状态。
5. 保存失败：保持输入，指出失败原因与重试；不要先关闭再用 toast 告诉用户失败。
6. 完成任务：明确是标记完成还是进入学习验收；产品语义由领域规则决定。
7. 返回：恢复原列表范围和上下文。对象被删除时聚焦邻近对象或列表标题。

### 必须设计的状态
- 空列表：说明当前范围为空，“创建任务”或“查看全部”依据原因选择。
- 筛选无结果：保留条件，提供清除筛选；不能伪装成首次使用。
- 加载中：保留可用外壳；短请求不必闪烁骨架屏。
- 本地读取失败：说明记录暂不可用，提供重试；不要静默重置为空库。
- 部分数据不可用：标记受影响区域，其余仍可用。
- 超长标题：允许换行或可访问全文，不能靠全部缩到小字。
- 多选：清楚显示数量和批量动作；退出多选不清空搜索。

### 对照
不佳：六张大统计卡占据首屏，任务在下方；每行只有悬浮后才出现完成。
改进：任务成为主体，统计退到页内摘要；完成入口有常驻目标与名称。
这只是本案例的选择；分析型产品可能应把指标放首屏。

## 3. 搜索与筛选页
先分清搜索的范围：全局找对象、当前列表内过滤、日历时间范围检索，不共用含糊的“搜索”反馈。
- 全局结果按对象类型分组，每项给标题、匹配摘要和来源，点击能到真实目的地。
- 输入与筛选是可编辑状态，结果是派生状态；请求返回时确认仍对应最新查询。
- 查询 A 后迅速输入 B：晚到的 A 不能盖住 B；可取消请求或使用请求序号。
- 清除搜索恢复原列表，不额外清除用户独立选择的日期或标签。
- 中文输入法组合期间不要抢占 Enter；快捷键只在非编辑状态处理。
- 不必每个按键都宣布结果；结果稳定后温和更新“找到 8 项”。
- 手机上的筛选可以用短 sheet，复杂筛选用完整页面；关闭时明确即时应用还是提交应用。

示例文案：
- “在当前清单中搜索”比“搜索所有内容”更准确。
- “未找到‘预算’。试试其他关键词，或清除标签筛选。”比“暂无数据”更可行动。
- “仍显示上次结果；更新失败，重试。”比隐藏已有结果更有连续性。

验收：清空、零结果、长查询、中文组合、键盘选择、快速连续请求、后退恢复。

## 4. 创建与编辑页
### 选择容器
| 情境 | 候选容器 | 理由 |
| --- | --- | --- |
| 快速捕捉一个标题 | 行内输入 | 最小切换成本 |
| 三五个紧密相关字段 | 短模态/Sheet | 明确提交与退出 |
| 长文、多段设置、复杂日程 | 完整页面或宽面板 | 键盘出现和错误展开后仍有空间 |
| 一边修改一边比较背景 | 非模态检查器 | 不必持续遮挡参考内容 |

字段数量不是绝对阈值，验证最坏状态：大字、长错误、软键盘、翻译和辅助技术。

### 原创字段例
标题“复盘本周阅读”，说明“用一句话描述要完成的事”；日期明确“计划日期”，不是模糊“时间”。
标题只要求必需内容；重要可选字段直接显示，低频高级字段渐进展开。不要把必需项藏在“更多”中。

### 保存策略
显式保存：适用于需要确认的一组更改，按钮文案“保存更改”。
自动保存：适用于连续编辑，必须有保存中/已保存/失败状态，以及离开页面的保护策略。
两者不能混杂成“字段似乎自动保存，关闭时却丢失”。

失败链路：
```text
editing → validating → saving → saved
             ↓            ↓
        invalid input   failed
             └── 保留草稿，定位问题，允许修正/重试 ──┘
```
校验失败不发请求；失败后不清空。单次 UI 防重不能代替后端幂等。
按钮 disabled 时需要能理解原因，不能仅变灰。错误避免只用红边。

退出未保存内容：复用当前产品的草稿/确认策略；若创建了新的行为模式，先确认。Escape、返回、点遮罩和关闭按钮应走同一保护逻辑。

## 5. 日历与时间规划
先说明时间语义，再选视觉网格：
- 日期任务只有一个当地日期；不能未经声明变成 UTC 午夜时间戳。
- 固定时区日程代表一个确定时刻；显示查看时区或来源时区。
- 浮动时间代表当地墙钟；跨时区旅行后的产品行为需明确。
- 全天开始/结束与时段日程不是同一字段，内部半开区间不要直接显示给用户。

周视图帮助看密度和冲突，议程帮助窄屏阅读和键盘访问。两者应对同一事件投影，不双写数据。
日/周/月切换保留时间锚点；“今天”改变锚点，不偷偷改用户的视图偏好。

拖动只产生候选位置；释放后校验权限、冲突、重复范围，再提交。
明确的反馈层次：当前位置 → 候选时间 → 冲突提示 → 提交结果。
总有“编辑时间”替代拖动。跨午夜、夏令时重复时刻、只读来源、隐藏日历都要验收。
重复事件修改时让用户看懂“仅这次/从这次起/整个系列”；只呈现真实支持的范围，不做空按钮。

空白网格点击创建时，把表单锚定到时间位置；软键盘遮挡时允许转为稳定面板。
不要让悬浮卡片覆盖用户刚选的时间且无法移开。

## 6. 设置页
设置不是功能仓库。按人的目的分组，如“外观”“输入”“提醒”“数据”，不要按内部模块名分组。
- 当前任务的排序留在列表，不放全局设置。
- 即时生效的主题切换应可逆且持续显示当前值。
- 全局偏好明确作用于本机还是所有设备；“跟随系统”与手动覆盖分别表达。
- 数据导入、清空、注销与外观开关不能混成同级小开关。
- 权限不可用时说明环境限制，例如“Web 预览不支持退出后的本机提醒”，而非“功能故障”。
- 长设置页有清楚分段与滚动归属；点击分段导航滚动内容，而不是整个窗口。
- 重置的是哪个范围写在按钮上，例如“重置字体大小”，避免泛化“恢复默认”。

示例：减少透明度启用后，导航、菜单、浮层都应回退，而不只改设置页预览卡。
验收：键盘到每个设置、刷新持久化、跨窗口同步、系统偏好变化、权限拒绝、取消危险操作。

## 7. 首次使用、空态与恢复
只解释立即需要的一个概念；让用户做一个真实任务。不是每个新特性都需要欢迎轮播。
演示数据必须标识为演示，并提供明确退出/清理方式；不能让用户误以为是自己的数据。
本地优先产品不要在能使用前强制登录。仅当某个能力确实需要账号时说明价值。
恢复流程优先保护输入与已有记录；异常后“重置全部”通常不是默认恢复动作。

## 8. 详情、阅读与专注
阅读页以内容行宽、行距与定位为重点；操作栏可以退让，但返回/退出仍可发现。
专注模式由用户进入，说明正在进行的任务，随时可暂停或结束。不要用锁定界面制造专注。
计时器可等宽数字；每秒变化不应每秒触发读屏播报。
长阅读支持选中、复制、正常滚动与键盘，不为了高级感禁用平台行为。
成功页反馈实际结果，避免夸大进度；下一步与用户刚做的事情相关。

## 9. 页面交付包
用一份代表流程串起页面，而不是一堆不相关屏幕：
- 入口与返回路径；
- 默认/空/错误/忙碌/长文状态；
- 宽窄窗口的同一对象；
- 主动作、焦点顺序、主要快捷键；
- 数据提交与恢复边界；
- 可执行的验收步骤和未验证项。
