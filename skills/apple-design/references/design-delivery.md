# 设计交付与示例任务
本页是本项目的操作方式，不是强制项目新建流程或文档。已有合同、设计系统与验收工具优先复用。

## 1. 四种使用深度
- 快速审查：一屏或一个组件，列出真实问题、理由与最小改动；不输出完整重设计。
- 页面设计：一个主流程，覆盖默认/错误/空/忙碌和宽窄窗口。
- 系统深化：多页面共享组件、token、状态与跨端映射；先找现有实现，避免重复系统。
- 实现验收：把已有方案落到代码，留交互/渲染证据和目标环境限制。

深度由用户的目标决定，不因为 Skill 长就每次读完全部参考。

## 2. 可直接使用的请求
### 设计一个主要页面
“使用本 Skill，为本地任务管理产品设计‘今天’页面。桌面支持列表—详情，手机采用分层导航。保留现有品牌，不增加统计卡片或云端。输出页面合同、关键状态、组件选择、键盘/触摸交互和验收步骤。”

应阅读 page-playbook、相关平台与组件章节。
合格结果应解释任务排序、第一屏优先级、进入/退出详情、创建失败后草稿留在哪里。
不合格结果：只有色板、圆角、玻璃参数和一张理想态图。

### 深化组件库
“审查当前 Button、Field、Dialog。给出状态矩阵、属性归属、输入与焦点行为，使用已有测试工具验证两个真实调用者；不要新建组件库。”

应阅读 component-contracts 与 code-implementation。
合格结果包含事件归属、关闭保护、错误关联、减弱透明度等真实边界。
不合格结果：只给每个组件套一层 blur。

### 做跨平台映射
“同一个任务编辑流程需要 Windows/Tauri、iPhone 和 Web。共享领域模型，允许导航与控件容器不同。请标注可共享部分、各平台差异、实现路径和逐平台验收证据。”

应阅读 cross-platform-playbook。
合格结果不会把 44pt 当作 Windows 通用值，也不会用 Web 截图证明手机原生通过。
不合格结果：所有平台用同一套屏幕尺寸和窗口按钮。

### 针对已有 UI 修复
“复现 390px 下长标题导致关闭按钮离屏。先定位共享根因，再做最小修复。检查常规文案、200% CSS 文字、高对比与键盘关闭。”

合格结果先有失败证据，再有修复和对应通过证据；不顺手更换字体或导航结构。

## 3. 方案评审的最小记录
```text
场景：在列表里编辑任务标题
当前证据：窄屏+长标题时右上关闭离屏
原则：阅读与主要动作不能因内容增长消失
选择：允许文本换行、约束内联尺寸，保留已有模态
替代方案：单行截断（拒绝：此处需要完整名称）
验收：390×844、长词、键盘返回；保存失败输入不丢
已验证：具体浏览器和命令
未验证：原生壳/真机/系统字体
```

## 4. 交付物的质量
设计稿标明哪些是真实产品、哪些是概念示意，不能把宣传图当验收截图。
组件规范包含状态和行为，而非仅默认尺寸；代码片段注明是否可直接运行。
工程示例给运行入口、依赖、预期结果和简化边界。
来源与日期放在适当参考处，更新时不要声称所有链接都重新核对过。
不把评审 Checklist 当形式门禁：每一项对当前任务是否适用应有判断。

## 5. 维护实例
新增案例时沿用“问题—决策—效果—边界”的结构：
- 新平台先补具体差异，不复制全部通用内容。
- 新组件先检查是否已由 Button、Field、Overlay 组合覆盖。
- 新故障优先纠正原规则；不要不断追加互相矛盾的绝对禁令。
- 示例预览的截图如更新，重新说明状态，不保留过期的通过标签。
