# 跨平台实现与验收
本页是工程映射，不是 Apple 官方 CSS 或组件 API。先复用产品现有 token、组件和测试；原生平台优先使用其系统能力。

## 从证据进入
1. 读产品合同、设计合同、当前分支、共享样式、调用者和相关测试。
2. 用真实代表任务记录入口、操作、结果，包含空、长文、失败、编辑和恢复。
3. 给问题关联具体 HIG 页面；先修复可操作性和可读性，再处理装饰细节。
4. 通过共享层的最小修改解决同类问题，检查其它调用者。
5. 记录修改范围、验证环境、可复现步骤和剩余缺口。

## Token 与字体
复用 primitive → semantic → component 的现有结构。语义至少区分背景、内容、功能层、浮层，主/次文字、边界、强调及状态。没有需求不要引入新的 token 框架。
大小优先相对单位；表单和列表用 min-height 允许字体增长。时间数值可以等宽数字。禁止把固定 iOS 字号、16px 边距或 Apple 系统色取样定义成全平台规范。
系统字体不需要下载 SF 文件。Windows、Android 和 Web 的字体、图标与系统操作应符合各自产品合同。

## 功能层材质
内容面先保证可读，功能面再增强。检查背景变化时的文字，浮层之间不要无限叠加 blur。透明度关闭或功能不支持时使用完全不透明背景，去掉 backdrop-filter。
工程写法依现有选择器；不要复制一套独立主题。prefers-reduced-transparency、prefers-contrast、forced-colors 与产品已存在的偏好都应触发同一语义回退。系统色 high-contrast 需覆盖内联颜色。
Scroll edge 只用于滚动内容和浮动控件实际交界；效果不拦截点击，也不遮住顶部/底部最后一条内容。为安全区与固定控件保留可滚动空间。

## 控件完整性
按钮有默认、悬浮、按压、键盘焦点、禁用、忙碌态；忙碌不重复写入。图标按钮有明确名称与可发现提示。
输入有名称、值、必填、无效和说明关联；placeholder 不替代 label。错误保留用户文字，不自动“纠正”成另一有效日期。
菜单、listbox、tabs、switch 根据实际语义选择角色；不能所有弹层都叫 menu。
模态有标题、焦点管理、背景隔离和退出；非模态不设假的 aria-modal。只有最上层处理 Escape。焦点返回处理原触发器已删除的情况。
列表中的“完成”与“打开详情”是不同目标；避免嵌套 button。选中、焦点与完成状态各自可分辨。
长内容可换行；确需省略时可访问完整内容。局部工具或日历可以横滚，页面整体不因控件最小宽度意外横滚。

## 数据与反馈
共享 capability/service 的成功结果驱动成功提示。保留现有事务、幂等、错误和撤销语义。
保存失败不关编辑器、不丢候选数据；长等待有反馈；可逆操作尽量有撤销。用户没启动的任务不凭设计优化自动执行。
普通任务、学习任务、重复项的产品规则独立于视觉组件，不因更换按钮或弹层绕过业务流程。

## 验证矩阵
按实际改动选择最小但足够的组合：
- 核心流程：创建 → 编辑 → 保存 → 完成 → 撤销/重开 → 刷新恢复。
- 视口：当前产品的宽桌面、最小窗口、窄屏及断点两侧。
- 内容：空、常规、超长标题、中文/数字、错误与处理中。
- 输入：鼠标与键盘，触摸目标；改到拖动时验证替代路径。
- 外观：浅/深色、减少动效、减少透明度、高对比；自定义主题产品抽查其它主题。
- 缩放：文字增长与回流；说明使用浏览器缩放、CSS zoom 或原生字体设置。
- 工程：相应类型/构建/测试门禁，console/page error，必要截图与交互断言。

语义快照可以证明名称与角色，截图可以证明布局，交互检查可以证明操作结果；三者不能互相代替。Web 不等于 Tauri，响应式不等于 iOS 原生。报告 native-simulator/native-device 仅在实际验证时使用。

## 优先级
P0：丢数据、误执行、无法完成主流程。
P1：关键操作不可达、焦点/键盘失败、主要文字不可读、缩放遮挡、状态误导。
P2：密度、视觉层级、对齐、次要反馈和一致性。
P3：不影响使用的细节打磨。
每条结论需要“复现/证据 + 影响 + 修改 + 验证”，不能只写“更 Apple”。
